# AWS IAM and Least-Privilege Security Project

## Project Overview

This project demonstrates the implementation of identity and access management controls in Amazon Web Services using the principle of least privilege.

## Objective

The objective was to secure access to AWS resources by creating users, groups, roles, permissions, and multi-factor authentication controls.

## Tools and Technologies

- AWS Identity and Access Management
- AWS Management Console
- Multi-Factor Authentication
- IAM Policies
- AWS Roles
- Least-Privilege Access Control

## Implementation

1. Created IAM users and security groups.
2. Assigned permissions based on job responsibilities.
3. Configured multi-factor authentication.
4. Reviewed access policies and removed unnecessary permissions.
5. Used IAM roles for controlled access to AWS resources.
6. Validated that users could access only authorized services.

## Security Principles Applied

- Least privilege
- Role-based access control
- Separation of duties
- Strong authentication
- Access review
- Identity lifecycle management

## Key Takeaways

- Excessive permissions increase the risk of unauthorized access.
- MFA provides an important additional layer of account protection.
- IAM roles reduce the need to use permanent credentials.
- Permissions should be reviewed regularly and adjusted as responsibilities change.
